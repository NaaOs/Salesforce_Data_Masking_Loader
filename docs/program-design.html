1. 概要

1.1 目的

本プログラムは、CSV ファイルに含まれる個人情報・機密情報を YAML で定義したルールに従ってダミーデータに置き換え（マスキング）、その結果を CSV として出力する、または Salesforce の SOAP Partner API を用いて Insert / Upsert するツールである。主に検証用 Sandbox へ本番相当のデータを安全に投入する用途を想定している。

1.2 機能一覧

No機能概要担当クラス
F01マスキング設定読込YAML ファイルを読み込み、オブジェクト／項目ごとのマスキングルールを生成し妥当性を検証するConfigLoader
F02CSV 読込・マスキングCSV を 1 行ずつ読み込み、設定対象項目をダミー値に置換するCsvProcessor / MaskingDataGenerator
F03マスキング済み CSV 出力（mask-only）マスキング結果を {オブジェクト名}_masked_{エポックミリ秒}.csv に出力するCsvProcessor
F04Salesforce Insert（mask-insert）マスキング結果をバッチ単位で create() するSalesforceConnection
F05Salesforce Upsert（mask-upsert）外部 ID 項目をキーにバッチ単位で upsert() するSalesforceConnection
F06CLI 実行コマンドライン引数で処理モード・オブジェクト・CSV を指定して一括実行するDataMaskingLoader
F07GUI 実行JavaFX 画面で設定ファイル・CSV を選択し、非同期で処理・進捗表示・ログ表示を行うDataMaskingApp / MainController

mask-upsertありSalesforce に作成または更新CLI: 省略時 Id ／ GUI: 必須

ConfigLoadercom.salesforce.tools.config
シグネチャ処理内容
public static MaskingConfig loadConfig(String configFilePath) throws FileNotFoundException
  1. FileInputStream でファイルを開く
  2. リフレクションで SnakeYAML 2.x 方式 new Constructor(MaskingConfig.class, new LoaderOptions()) を試行
  3. 失敗時 1.x 方式 new Constructor(MaskingConfig.class)、さらに失敗時 new Yaml() にフォールバック
  4. yaml.load() で MaskingConfig にマッピングし、オブジェクト数を INFO ログ出力
public static boolean validateConfig(MaskingConfig config) 以下を検査し、NG は ERROR ログ出力して false。
  • config / objects が null または空 → NG
  • オブジェクト名が null または空 → NG
  • fields が null または空 → WARN のみ（継続）
  • 項目名が null または空 → NG
  • maskingType が null → NG
※ FIXED_VALUE の value 未設定、length の値域は検査しない
CsvProcessorcom.salesforce.tools.csv

コンストラクタで MaskingDataGenerator を 1 つ生成して保持する。レコードは Map<String, Object>（実体は HashMap）で表現する。

シグネチャ処理内容
public List<Map<String,Object>> readAndMaskCsv(String inputCsvPath, ObjectConfig objectConfig) throws IOException
  1. 1 行目をヘッダーとして読込（null なら空リストを返す）
  2. データ行ごとに、ヘッダーの各列（前後空白 trim）について objectConfig.getFieldConfig(列名) を検索
  3. 設定ありの列は generateMaskedValue() の値で置換（元値は参照しない）、設定なしの列は元値のまま格納。列不足は空文字
  4. 1,000 件ごとに進捗 INFO ログ
  5. CsvValidationException は IOException("CSVフォーマットエラー") に変換
public void writeMaskedCsv(String outputCsvPath, List<Map<String,Object>> records) throws IOException先頭レコードの keySet をヘッダーとして出力し、各レコードの値を文字列化（null は空文字）して出力。0 件時は WARN を出して何もしない
public List<Map<String,Object>> readCsv(String csvPath) throws IOExceptionマスキングなしで CSV を読み込む（現状どこからも呼ばれていない）
MaskingDataGeneratorcom.salesforce.tools.masking

Faker(Locale.JAPAN) と java.util.Random を保持し、generateMaskedValue(FieldConfig) で MaskingType に応じた値を返す。fieldConfig または maskingType が null の場合、および生成中に例外が発生した場合は null を返す（例外は ERROR ログのみ）。各タイプの生成ロジックは 7. マスキング仕様 を参照。

SalesforceConnectioncom.salesforce.tools.salesforce
シグネチャ処理内容
public void connect() throws ConnectionExceptionConnectorConfig にユーザ名、パスワード＋トークン、認証エンドポイント（loginUrl）を設定し Connector.newConnection() でログイン。ログインユーザのフルネームを INFO ログ出力
public List<SaveResult> insertRecords(String objectName, List<Map> records) throws ConnectionException
  1. レコードが空なら WARN を出して空リストを返す
  2. batchSize 件ずつ subList で分割
  3. 各レコードを createSObject() で SObject に変換
  4. connection.create(sObjects) または connection.upsert(externalIdField, sObjects) を呼出
  5. 結果ごとに成功／失敗を集計、失敗時はエラーメッセージを ERROR ログ。バッチ単位で件数を INFO ログ
  6. ConnectionException はログ出力後に再スロー（以降のバッチは処理しない）
レコード単位の失敗は例外とせず、結果リストに含めて返す
public List<UpsertResult> upsertRecords(String objectName, List<Map> records, String externalIdField) throws ConnectionException
private SObject createSObject(String objectName, Map<String,Object> fieldMap)type を設定し、値が null でない項目のみ setField（空文字はそのまま設定される）
public void disconnect()connection 参照を null にする（logout() は呼ばない）
public PartnerConnection getConnection()内部接続を返す

7. マスキング仕様

MaskingType生成ロジックパラメータ出力例
RANDOM_STRINGRandomStringUtils.randomAlphanumeric(length)length（既定 20）aZ3k9QwP0mLx7Rt2YbN1
PHONE"090-%04d-%04d" に 0〜9999 の乱数 2 つ-090-0427-8815
EMAILfaker.internet().emailAddress()-(ロケール依存の文字列)@example 系ドメイン
FIRST_NAMEfaker.name().firstName()-翔太
LAST_NAMEfaker.name().lastName()-佐藤
ADDRESSfaker.address().fullAddress()-ロケール依存の住所文字列
COMPANY_NAMEfaker.company().name()-ロケール依存の会社名
FIXED_VALUE設定値をそのまま返すvalue（未設定時 null → Salesforce へは送信されない）MASKED
NUMBERrandom.nextInt(10^length − 1) を文字列化length（既定 10）48213
DATEfaker.date().birthday() を yyyy-MM-dd で整形（18〜65 歳相当）-1987-04-12

共通仕様

  • 元の値は参照せず、毎回独立した乱数で生成する（同一値に対する一貫性・再現性はない）。
  • 元の値が空欄であっても、設定対象項目であればダミー値が設定される。
  • 設定にない列は元の値をそのまま出力・投入する。

9. 課題・改善提案

ソースコード解析の過程で確認された、仕様上の注意点および不具合の可能性がある箇所を示す。

No重要度箇所内容改善案
9.1高pom.xml / ObjectConfig, MainControllerStream.toList()（Java 16+）を使用し、JavaFX 21 は Java 17 以上が必要。一方 pom は source/target 11、README は「Java 11以上」と記載しており実際には Java 11 で動作しないmaven.compiler.release を 17 にし、README の動作要件を Java 17 以上に修正
9.2高README / pom.xmlJAR の Main-Class は GUI（DataMaskingApp）のため、README 記載の java -jar ... mask-only Account accounts.csv では CLI ではなく GUI が起動するREADME の CLI 例を java -cp <jar> com.salesforce.tools.DataMaskingLoader に統一、または引数有無で振り分けるランチャーを用意
9.3高SalesforceConnection / 呼出元レコード単位の Insert/Upsert 失敗がログのみで、GUI は「正常に完了しました」と表示し、CLI も終了コード 0 になる結果を集計し失敗件数を画面・終了コードに反映、失敗レコードを CSV 出力
9.4中CsvProcessor.writeMaskedCsvレコードが HashMap のため出力 CSV の列順が入力と異なるLinkedHashMap を使用、またはヘッダー配列を保持して出力
9.5中CsvProcessorFileReader / FileWriter が JVM 既定文字コードを使用し、Windows（MS932 既定）で UTF-8 の日本語 CSV が文字化けする可能性Files.newBufferedReader(path, UTF_8) 等で文字コードを明示（BOM 対応も検討）
9.6中MainController.executeAsyncTask（バックグラウンドスレッド）内で ComboBox / TextField の値を参照しており、JavaFX のスレッドルールに反するTask 生成前に UI スレッドで値を取得し、final 変数で渡す
9.7中SalesforceConnection.createSObject空文字の値も setField されるため、数値・日付項目などの空欄で型エラーとなる可能性。Upsert 時は意図せず値をクリアする可能性もある空文字をスキップ、または fieldsToNull で明示的に扱う
9.8中全体全レコードをメモリに保持してから処理するため、大量データでメモリを圧迫する。DEBUG ログで全項目のマスキング値を出力するため、ログ量も大きいストリーミング処理（バッチ単位で読込→投入）、Bulk API の採用、既定ログレベルを INFO に
9.9低ConfigLoader.loadConfigFileInputStream がクローズされない。リフレクションによる SnakeYAML の版判定は 2.2 固定のため不要try-with-resources と new Constructor(MaskingConfig.class, new LoaderOptions()) の直接呼出しに置換
9.10低ConfigLoader.validateConfigFIXED_VALUE の value 未設定、length の範囲（NUMBER は 10 以上で int 上限に丸め）を検証していないタイプ別の追加検証
9.11低DataMaskingLoader / MainControllerexecute* と loadSalesforceConfig のロジックが重複共通サービスクラス（例: MaskingService）へ抽出
9.12低SalesforceConnection.disconnectlogout() を呼ばずセッションが残るconnection.logout() を呼ぶ
9.13低セキュリティパスワード・トークンを平文 properties で保持（salesforce.properties は .gitignore 登録済み）OS の資格情報ストア利用、OAuth（JWT Bearer 等）への移行
